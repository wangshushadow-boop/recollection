任务 P2-FIELD-INTEGRATION-024、025。交付提交 `50e11a2`，分支 `codex/p2-field-frame-preview`。从主菜单进入河原，点击开始野战后站立。RTX 3090、Core Ultra 9 285K、Godot 4.7.2 Standard、Forward+、960×600，种子 241124，500 人（250 步兵、150 弓兵、50 骑兵、50 骑射）和 100 匹马。两版均用 60 Hz 规则，每显示帧最多执行 2 个战斗步。

每轮独立启动客户端。部署停留 45 帧，稳定窗口为第 121–440 步。FPS 与步速使用相同完整显示帧的总墙钟时间计算，P50/P95 采用最近秩。基线和交付版各 1280 步，各有 637 和 636 个窗口内完整显示帧，全部执行两步。平均帧时间 79.31 → 73.04 ms，帧率变化 +8.6%。同布局下比较三个线程池分片数，计入建任务、等待、归并和后续整帧工作。共六次并行进程在第 118、119 步逐行核对 600 条投影、行序及缓存命中，均与串行结果一致。生产使用串行版本。

四分片平均只多 0.05 FPS，帧时间 P95 增加 1.69 ms。串行四轮的轮间波动已超过该平均差值，两分片和八分片的平均 FPS 均低于串行。另在每个分片候选运行野战流水线的伤亡增援、上下马、拒绝回滚和重试，每版均通过 334 项。回滚路径的正确性在无头环境验证，正常站立采样的窗口内没有注入故障。

## 时间和工作量

- 移动 `_walk` 平均 10.73 → 11.13 ms/步，AI `_think` 10.91 → 10.53 ms/步，战斗 `_fight` 2.69 → 1.37 ms/步。整数战斗位置的准备已移入移动阶段。原版的物理行与整数位姿两个打包阶段合计 2.73 ms/步，交付版同一批输出的准备为 2.63 ms/步。
- 每步输出 600 条投影，平均复用 449.4 条完整投影。引擎平均识别出 371.6 条此前提交且持续只读的同一物理输入。其余行执行常规校验。物理阶段 2.60 → 1.89 ms/步。仅速度改变时也会生成新的物理输入，这会让部分几何相同的行继续走常规校验。
- AI 输入装配 1.79 → 1.48 ms/步。显示时的可见性筛选 3.37 → 1.68 ms/帧，完整视觉投影 6.28 → 4.32 ms/帧。每次仍向场景查询敌方视线。新版个体 AI 的感知、决策与收集为 4.37 ms/步。移动推进与避让为 3.72 ms/步。

## 代码与验收

- `game/mission/runtime/field_pipeline.gd` 在移动结束后为同一代际实体生成显示姿态、物理输入和整数战斗姿态。AI 在稳定名册上读取前一步提交的位置与原始朝向，并应用当步的观察方向。动态战斗状态保持当步读取。发布和回滚沿用现有顺序。
- `game/mission/runtime/field_mission.gd` 用实时实体行和本次提交的名册过滤可见角色。角色返回值仍可独立修改。
- `game/infrastructure/engine/field_bodies.gd` 识别同一已验证的不可变物理输入，保留同批重复编号、移动、回滚、退役与代际复用的检查。引擎回归位于 `game/tests/p2/field_engine/run.gd`，投影回归位于 `game/tests/p2/field_pipeline/pose_projection.gd`。
- 独立 QA 的 15 套无头回归全部通过，另行对比基线和交付版 1,260 步有指令实战，每步摘要相同。首伤第 986 步，88 次发射、61 次正伤害命中、总伤害 2,112。覆盖四类兵种移动、遇墙、上下马、跳跃落地、可见性、句柄换代、拒绝后重试和事务回滚。主 Agent 在最终工作区另跑物理 86 项、投影 30 项、AI 1,337 项，均通过。[无头回归原始证据](qa.zip)

本轮未测资源初始化耗时、两军混战时的桌面 FPS、1000 人场景及其他硬件。30 FPS 和每现实秒 60 步均未达到。P2 整体性能门禁继续保留。

## 复跑

准备 Godot 4.7.2 已导入的工程，分别取 `ec87e24` 与 `50e11a2`。中间串行版从交付版恢复原版的 `infrastructure/engine/field_bodies.gd`。解压 desktop.zip，在脚本目录执行 `python prepare.py A <基线game目录>`、`python prepare.py C <交付版game目录>`。设置环境变量 `RECOLLECTION_IDLE_CAPTURE` 为一个输出 JSON 的绝对路径。各版本以 `Godot --path C/game --script <idle.gd绝对路径> -- --profile=client` 顺序运行，替换相应工程目录。线程候选执行 `python workers/prepare.py C/game`。轻量数据用 `python flat_stats.py <一轮或多轮JSON>` 汇总。分阶段副本用 `python flat_probe.py C CD`，再执行 `python pose_probe.py CD/game`。基线对应使用 `crit_probe.py`。
