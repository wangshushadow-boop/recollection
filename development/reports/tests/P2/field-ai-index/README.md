# 单机河原野战 AI 编队成员索引

任务 P2-FIELD-INTEGRATION-023。基线 `079c24e`，候选 `f1bdb4e`，本地桌面客户端每帧最多补算 2 步。两版使用相同的 60 Hz 规则、画质、种子 241124、500 名士兵和 100 匹马。桌面从主菜单进入河原，部署 45 个显示帧后点击开始，玩家全程站立。

## 实现与行为

游戏修改集中在 `game/mission/runtime/field_brains.gd`。AI 每步依然读取编队权威视图，按组使用上次已提交的“兵员编号 → 代际”索引。修订号与成员快照同时匹配才能复用；成员关系变化时重建该编队。提交后才发布候选索引，回滚或拒绝步保留原索引。输入仍逐人校验，实际执行时的撤权、视野、目标、位置、生命、弹药、朝向、命中及步频沿用原有逻辑。

独立 QA 和主 Agent 在最终工作区均运行 `--headless --fixed-fps 60 --path game --script res://tests/p2/field_brains/run.gd`。针对旧代际、错类型、额外字段、重复句柄、转队、重排、撤权和回滚重试的专项前后各通过 1,337 项，均触发 5 个战术、55 个编队、80 个个体任务。编队、事务和真实野战流水线等其余五套回归也全部通过。500 人及 100 匹马的有指令野战与上一版已验证的逐步记录对比，1,260/1,260 步状态摘要相同，第 986 步首次命中，88 次发射、61 次正伤害、总伤害 2,112。[独立验收与原始记录](qa-evidence.zip)

本轮只验收河原 AI 名册优化。混战阶段帧率、1000 人性能、其他 GPU 和完整 P2 门禁本轮未测。30 FPS 目标尚未达成。

## 复跑

解压桌面证据包，分别准备已导入的基线和新版工程，并为两版应用随包的 `local-2-step.diff`。使用 `python prepare.py <label> <game目录>` 生成轻量计时副本。将 `RECOLLECTION_IDLE_CAPTURE` 指向输出 JSON，桌面启动参数为 `--path <label>/game --script <idle.gd绝对路径> -- --profile=client`。附加细采样先执行 `python idx_probe.py <label> <probe-label>`，再从新副本走同一入口。完整战斗步与帧时间可用 `flat_stats.py <原始JSON文件> ...` 复算。
