## 实现与选择

个体 AI 只给本步已获调度的士兵计算候选。工作线程读取当前步的空间网格，分别计算并排序附近的友军与敌军。主线程仍按原始任务顺序做视线、寻路和权限检查。没有敌方候选时，可将多个士兵的动作决策一起分片，最后由主线程逐项校验移动目的地并接纳意图。出现敌方候选时先接纳上一组任务，再按原顺序处理当前士兵。小批量自动走串行。

生产变更位于 `game/mission/runtime/field_brains.gd`、`game/mission/ai/perception/field_perception.gd`、`game/mission/ai/ports/field_ai.gd` 和 `game/mission/ai/individual/ports/field_individual.gd`。专项回归位于 `game/tests/p2/field_brains/quiet_blocked.gd`。

移动实验把目标、朝向、落点和静态范围计算拆为分片，仍在主线程按原顺序处理动态占用、让行、撤权和跳跃。实测 2、4 批移动均慢于原实现，交付版采用原移动代码。桌面证据包内保存了实验源码和相对基线的补丁，可单独复验。

## 无头行为

独立 QA 在 2 批候选和最终交付版各回放同一段有指令的 500 人、100 马战斗。两者均与既有基线的 1,260 个逐步摘要完全相同。第 986 步在移动和战斗后注入失败，公开状态保持在 985，重试后首次命中仍在 986。全程 88 次发射、61 次正伤害命中、总伤害 2,112。另对寻路被拒后的停止与放下防御做了针对性回归，12 项通过。主 Agent 在交付工作区复跑这 12 项。未测混战阶段的桌面帧率、千人场景或其他硬件。[接战与回滚证据](qa.zip)

## 复现

解压桌面证据，准备已导入的基线与交付版 game 目录。在各自副本上用 `prepare.py` 加完整步探针，再用 `flat_probe.py` 加相同的阶段计时。要生成移动实验的三档副本，先复制交付版，用包内 `candidate/field_movement.gd` 替换该副本的移动脚本，并将 AI_BATCHES 暂设为 2，然后运行 `python jobs_prepare.py <副本game目录>`。交付版采样使用 4 批实验探针副本，恢复基线已加探针的移动文件。设置环境变量 `RECOLLECTION_IDLE_CAPTURE` 为输出 JSON 的绝对路径，逐个启动 `Godot --path <本次game> --script <idle.gd绝对路径> -- --profile=client`。可用 `python flat_stats.py raw/JobsRelease.json` 复算交付版。
