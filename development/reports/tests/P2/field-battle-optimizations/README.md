# 河原野战四项优化验证

对照基线为 `9365806`，Godot 4.7.2 Standard，Linux x86_64。两版使用相同引擎、种子 241124、60 Hz 规则和操作序列。性能样本来自共享 CPU 的无头运行，本报告未测桌面帧率和 GPU 耗时。

## 变更范围

- 战术、阵型和单兵任务按原顺序提交。只为这一轮有编队任务的阵营读取战术计划。
- 并行排序按候选工作量决定分片数，低威胁单兵的纯决策由主线程与工作线程共同计算。视线查询和指令提交保持原序。
- 移动结果、视线朝向覆盖、瞄准及装备条件稳定时，共享已提交的位姿快照；首次写入时再复制。部分士兵发生变化时仍逐人核对。人员或骑乘关系变化时重新建立对应关系。
- 远景保留姿态分组和 MultiMesh，只向引擎提交变化的实例槽，容量变化后重新填充。近景复用固定的骑姿和骨骼静止旋转。

## 复验方式

在每个工作树导入游戏资源后，用 Godot 执行随基线归档的实战验证程序。每轮独立启动，比较输出 JSON 的 `checksums` 以及战斗汇总。比较耗时时，在 `app.field_step()` 前后取单调微秒时钟，统计第 121 至 1260 步的 1140 个样本。计时范围不包括等待物理帧、读取视觉报告或生成校验摘要。

```bash
unzip -p development/reports/tests/P2/field-pose-batch/qa.zip behavior.gd > /tmp/field-four-behavior.gd
RECOLLECTION_QA_COUNT=500 RECOLLECTION_BEHAVIOR_PROOF=/tmp/field-result.json \
  godot --headless --fixed-fps 60 --path game --script /tmp/field-four-behavior.gd
```

位姿 44 项、引擎 94 项、移动批处理 3359 项、骑乘视觉 102 项通过；视觉功能套件通过。野战 AI 集成测试 1366 项通过。独立 AI 混合负载套件在基线与候选上均有两个失败：测试输入在第一步提交的防御指令被拒绝，不能据此套件报告 500/1000 人吞吐。P2 的桌面性能门禁仍待目标机实测。

## 500 人与 100 匹马的逐步对照

六次运行中，1,260 步各步的角色、弹道及战斗事件摘要均与基线一致。首伤第 916 步，126 次发射，119 次正伤害命中，总伤害 2982。

每版独立运行三轮，依次为基线、新分支、新分支、基线、基线、新分支。单位为毫秒。

| 运行 | 平均 | P50 | P95 |
|---|---:|---:|---:|
| base | 41.04 | 38.91 | 56.41 |
| final | 44.31 | 38.34 | 70.52 |
| final2 | 38.31 | 36.78 | 49.79 |
| base2 | 36.46 | 35.04 | 43.42 |
| base3 | 41.34 | 39.91 | 50.89 |
| final3 | 43.40 | 41.36 | 55.55 |

基线合并 3420 步，平均 39.61，P50 38.27，P95 50.90 ms。

新分支合并 3420 步，平均 42.01，P50 38.94，P95 66.00 ms。

共享主机上不同轮次有波动，本次整步数据不能证明整体提速。另做了 600 实例的无头 CPU 批次提交微基准，三轮静止场景的中位值从 674 降至 490 微秒，全员移动从 673 降至 626 微秒。该测量不包含实际 GPU 绘制。
