# 河原野战 C++ 推进与避让试验

P2-FIELD-INTEGRATION-033。基线为移动第二版 `5277bd4`。本次交付 Windows x64 独立试玩版；日常游戏继续使用 GDScript。双击[试玩 C++ 野战](试玩C++野战.cmd)，从主菜单进入河原。脚本从固定 Git 提交建立独立游戏目录，解包已测试的 DLL，导入资源并实际调用内核自检。用户数据也保存在该副本内。

## 一轮同机桌面对照

Core Ultra 9 285K、RTX 3090、Godot 4.7.2 Standard、Forward+、960×600，种子 241124，500 名士兵、100 匹马。维持 60 Hz、每帧最多补算两步。每版启动两次，从相同菜单和部署进入。站立无输入；第二场第 1 步后给四阵下达移动命令，第 900 步发自由攻击。站立和行军各取第 121–440 步，接战取第 986–1260 步；只计完整落入窗口的显示帧。进场资源初始化未计入。

三段窗口内，每步均有一次真实原生批调用。行军平均约 399 名步兵在 C++ 中计算朝向、步长、候选落点和顺序避让，100 名骑兵在脚本中计算转向和落点、在 C++ 中参与避让，1 名玩家由原脚本处理。统计单位为移动域中的士兵；坐骑的物理代理另外同步。已观测的逐步让行、AI 调度、物理写回、发射、命中与伤害一致。候选直接重复几何计算，接战平均每步近邻精查 2212 次，原版依靠上一阻挡者的结果复用仅需 942 次。

行军时，脚本侧准备平均 2.590 ms/步，包括权限与路径状态检查、骑兵候选计算、装配连续数组；原生调用及返回平均 0.133 ms，按原顺序写回平均 0.333 ms。外层推进计时还含分段、回退和循环等成本。整帧平均收益约 1.9%–3.0%，每种输入各一组对照，无长期置信区间。维持自选试玩，未把 DLL 加入默认启动或发布依赖。下一项可检验的是让 MOV 复用已有的连续位置与控制数据，减少每步脚本准备时间。[逐项采样](summary.json) · [原始显示帧、步数据与桌面探针](desktop.zip)

## 行为及集成回归

- 独立无头回放 1260/1260 步角色位姿、投射物及战斗事件摘要逐步等于参考。1249 个成功步进入 DLL，计数器累计 1402 批（含故障尝试）。第 986 步故障和重试各进一次 DLL；失败后仍显示第 985 步，重试首伤在第 986 步，全程 88 发、61 次有效命中、2112 点伤害。
- 72 人、94 步的独立移动用例通过 7891 项检查。覆盖 48 个邻居上限、零位移、跨格、不同格内次序及原序腾位。145 个原生批处理了 6429 行，骑兵发生 4 次跨格，50 个空中步与其他单位的原生移动同时发生且正常落地。
- 扩展导入与内核烟测通过，含 256 个随机目标的步兵落点和朝向比对。已核验同一 DLL 用于实测与试玩，SHA-256 为 `8da02c3c41b147be23a9a8727b52a33897d62fc6e559d46f6c41f8d1471240e6`。审查后为试玩清单增加最大兼容版本 4.7.2，启动器集成自检通过。首次启动器检验暴露 Windows 行尾和自检脚本类型推断问题，两项修复后重跑退出 0。
- 候选只对正式野战发放的内部 AI 凭据启用原生批。外部玩家、空中、门廊、有特殊地形约束的移动，以及过短的连续区间保留原有更新顺序。GDScript 仍负责授权、事务和提交。未测千人门禁、其它平台及跨机器逐位一致性。
