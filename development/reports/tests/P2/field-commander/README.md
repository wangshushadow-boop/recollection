# 河原主将、观察镜头和全军冲锋

2026-11-26。基线 `d74a35d`，主将、AI 和镜头 `9ea0676`，经密集交战修复的试玩版本 `6733b06`。普通和 C++ 常驻版使用同一人物、输入和战斗 AI。常驻包中的运行时装配脚本已同步英雄的战斗主将标记，并重新校验文件；原生移动 DLL 沿用原版本。

## 试玩操作

| 场景 | 操作与结果 |
|---|---|
| 第三人称站立 | 移动鼠标可绕主将观察，包括看见正面。行走时主将逐步转向视线，按下攻防键时准星和权威攻防朝向对齐。R 切换第一人称；按住反引号也可在移动中单独环视。[实机正面及属性](face.jpg) |
| 主将与背包 | 右下显示人物等级、当前/最大生命、士气和体力规则。I 打开或关闭随身装备，Esc 也可返回。从菜单打开则先回菜单。行装只显示本人在本场携带的东西和当前使用状态。[实机行装](inventory.jpg) |
| 全军进攻 | 依次按主键盘 0、F1、F3。先选全队，再进入移动菜单，最后发出冲锋令。提交成功后屏幕显示冲锋和接令的编队数。也可以先按 1–4 只选一队。[实机回执](issued.jpg) |

练兵英雄通过现有角色创建系统在内存生成，出生等级 1，占已有编队的一个名额。练兵场不会读写玩家的战役人物。战斗主将身份用于现有士气规则。当前规则没有动作体力消耗，故显示「体力不限」。默认出战长枪，无远程配装时不显示弹药。士兵模型自带的盾甲属于外观，现在的长枪配装没有可卸下的盾甲物品。战役中从「人物 → 行装 → 行囊」查看物资或穿卸装备。

## AI 诊断和实测

河原开局双方位于感知距离之外。基线的四队都接收了普通冲锋命令；编队进入冲锋状态后，没有已知敌阵和明确落点，个体仍往原阵位移动。守兵已有合法的贴身自卫，在几米外会选中玩家却留在原地。

本版普通冲锋沿己方退场区通向公开战场目标的方向搜索，服从可走区域，发现目标后交给现有接敌与命中判定。军官自动驻守的士兵可在原岗 6 米内拦截已感知敌兵，目标离开后回岗。明确下达的「坚守」维持原地防卫。

## 验收证据

Windows / RTX 3090，960×600，普通版桌面 47/47、常驻版桌面 48/48，均实际推进到第 2401 步，并能从战场正常撤退返回。常驻版额外核验了原生内核调用。测试包括没有鼠标转动时的首次横移与随后攻防方向、站定环视到面前、步行平滑转身、第一人称和自由观察切换、打开行装及从菜单和战斗分别返回。默认主将站定环视约 170° 时身体保持原向。首版两份失败日志与最终成功日志均在证据包中。

双入口第一次延长实测，都在第 1885 步因 `sweep_contact` 退出。相同弹道的专项测试在旧版有 3 项失败。一支半径 15 毫米的箭擦中骑兵碰撞体，初次球扫报相交，后续采样却已越过人体。修复在这种罕见情况才检查整段扫过的体积并找回最早接触。若物理查询确实临时不可用，客户端在新的物理帧最多重试两次同一未提交步，命令沿用原序号。真实相交、略微错开、前方薄盾与忽略指定物体的情形均有回归，最终球扫测试 41/41；注入一次失败的事务在两次尝试后只推进一步。

两档无头 HUD 各 201 项通过；输入回归 411 项通过；守岗 306、个体 AI 910、战斗 AI 集成 1366 项通过。普通和常驻版的单机开场回归均核对主将身份及上限、装备、20 名在场与 40 个源槽。独立初审发现并修复了开场首次横移可能令准星与出招相差 90° 的问题，也修复了规则与战斗使用不同主将标记的问题。

[桌面断言、原始日志和复现脚本](evidence.zip)。解压后在 Windows 运行 `python run.py <游戏目录> normal` 或 `python run.py <常驻游戏目录> native --native`。以 `stand` 开头的标签复验约 4 米停车，以 `contact` 开头的标签复验持续接近。无头从仓库根运行 Godot `--headless --path game --script res://tests/p2/field_player_contact/charge.gd`；将脚本改为 `res://tests/p2/field_player_contact/run.gd -- --stand-off` 可复验停车后的截击。
